# AvaSeek

*In-Vehicle Assistant Design Parameter*

---

## IVA Avatar

This repository holds the **avatar package** from that project, extracted so it can be
used on its own: a fully parameterised, procedurally drawn assistant face for Unity.
The optimisation side is not included here - the avatar is optimizer-agnostic and can
be driven by anything that produces named values.

Every facial feature — the face outline, eyes, pupils, mouth, ears, stroke style, colour
and waveform — is a **named, ranged parameter**. Nothing is modelled, textured or
imported: the whole face is generated from `LineRenderer` strokes at runtime, so it costs
nothing to ship and can be reshaped continuously along 32 independent dimensions.

That makes it useful whenever a face has to be *searched* rather than *authored* — user
studies on appearance, A/B design comparisons, parameter sweeps, or any optimizer that
proposes values and wants to see the result.

## Install

Unity **2022.3 or newer** (verified on 2022.3 and Unity 6). Works with the Built-in Render Pipeline and URP (the material
shader is resolved with a fallback chain, no shader asset is shipped).

**Package Manager → Add package from git URL:**

```bash
https://github.com/lzh0717/AvaSeek.git
```

## Try it in 30 seconds

1. Open any scene.
2. Menu **GameObject ▸ IVA Avatar ▸ Demo (camera + avatar + sliders)**
3. Press **Play**, and drag the sliders.

The demo builds itself: an orthographic camera framing the face, the avatar, and a
scrollable panel with one slider per parameter. The panel is generated by reflection — if
you add a parameter to `IVARenderer`, a slider for it appears with no extra code.

### If the strokes look jagged

The face is drawn as thin `LineRenderer` strokes, so it needs multisampling to look clean -
and a freshly created project usually ships with it turned off. Turn MSAA on:

- **URP** - select your render pipeline asset (`Assets/Settings/*_RPAsset.asset`),
  then **Quality > Anti Aliasing (MSAA) > 4x**. Quality Settings has no effect on MSAA in URP.
- **Built-in** - **Edit > Project Settings > Quality > Anti Aliasing > 4x Multi Sampling**.

The Scene view has its own anti-aliasing toggle, separate from both.

If the face is simply too large on screen, raise **Orthographic Size** on the camera's
`IVACameraSetup` component - a bigger value zooms out.

## Driving it from your own code

The point of the package is that you never write per-parameter code:

```csharp
using IVAAvatar;

// Every parameter, by name, with its bounds
foreach (string name in IVAParameters.Names)
{
    IVAParameters.TryGetRange(name, out float min, out float max);
    IVAParameters.TrySet(avatar, name, Random.Range(min, max));
}

// Or one at a time - values are clamped into the parameter's [Range]
IVAParameters.TrySet(avatar, "mouth_curve", 0.8f);
IVAParameters.TryGet(avatar, "eye_width", out float w);
```

`TrySet` returns `false` for an unknown name, so a typo surfaces instead of silently
turning into a no-op. This is the intended write path: the avatar's own animation never
writes these fields, so an external driver and the face never fight over a value.

## What's in the box

| File | Role |
|---|---|
| `Runtime/IVARenderer.cs` | The face. All 32 parameters, all geometry, all drawing. |
| `Runtime/IVAParameters.cs` | By-name get/set/range access to every parameter. |
| `Runtime/IVAParameterPanel.cs` | Self-building slider panel (the demo UI). |
| `Runtime/IVACameraSetup.cs` | Frames a camera on the avatar as a flat, undistorted 2D view. |
| `Editor/IVAAvatarMenu.cs` | Scene-setup menu items and a parameter dump. |

## The parameters

**Face** `face_width` `face_height` `face_sides` `temple_width` `cheekbone_width` `jaw_width`

**Eyes** `eye_width` `eye_height` `eye_spacing` `eye_position_y` `eye_inner_curve`
`eye_outer_curve` `eye_tilt` `eye_roundness` `pupil_size`

**Mouth** `mouth_width` `mouth_curve` `mouth_position_y`

**Ears** `ear_width` `ear_height` `ear_curve` `ear_position_y`

**Style** `stroke_width` `wave_amplitude` `wave_speed` `glow_intensity`

**Colour** `color_saturation` `color_spread` `color_hue` — a continuous space: a sweep moves
smoothly from flat white, through a single vivid colour, to a full flowing rainbow. There is
no discrete colour mode to switch between.

Run **Tools ▸ IVA Avatar ▸ Log Parameters** to print every name, range and current value.

### The waveform state

The waveform is not a separate element — it is the face outline's *degenerate* state. When
`face_height` collapses to ~0 while `face_width` stays positive, the renderer draws an
animated waveform *instead of* the face. The two are mutually exclusive, so a parameter
sweep can travel continuously between "a face" and "a voice waveform" without any mode flag.

### Fitting into a fixed slot (optional)

Off by default. Set `autoFitToSizeFrame = true` and `hostObjectName` to the name of an
object already in your scene, and the avatar scales uniformly to the largest size that fits
that object's height — and keeps re-fitting as its shape changes. If no such object exists,
auto-fit does nothing and the authored Transform scale is kept.
